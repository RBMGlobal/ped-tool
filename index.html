Layers — key & filter
Plot points
Points go to the layer chosen above — “➕ New layer…” starts a fresh one. Enter a coordinate, or “Pick on map” then click the map. Import CSV / GeoJSON / KML / GPX by dropping the file on the map — imports with points ask which layer to add them to (existing or new). To re-home a point later, open its popup and change its Layer.
Bulk paste — scan any text for coordinates
Or drop a WhatsApp chat export (.zip), .docx, .pptx or .txt file straight onto the map — its text is extracted and scanned the same way. In a chat export, shared pins are read as well as typed coordinates, each point is named from the message beside it, the sender and timestamp go into its notes, and photos sent with the pin are attached to it (they travel inside the TAK package). Found points use the affiliation / type chosen in the box above and the layer picked under the list — an existing layer or “➕ New layer…”. Untick any false hits before adding. (Photos/screenshots of coordinates can't be read offline — copy the text out, or use CSV for spreadsheets.)
Team iconset (ATAK)
Icons your team's ATAK devices already carry — copy the path from ATAK's Iconset Manager. Points using one export with that iconsetpath; on this map they show as a coloured pin stand-in. Saved with the project.
Routes (Google Maps / GPX → TAK)
Paste a .../maps/dir/… link that contains coordinates (a shared maps.app.goo.gl short link carries no coordinates — the tool opens it for you; copy the full URL from that tab's address bar). Stops are read in order and each leg snaps along roads at full resolution (~5 m fidelity). Note the road choice comes from OSM routing, which can pick a different road than Google at some junctions — eyeball the line before relying on it. For Google's exact line: build the route in Google My Maps (add driving directions) → ⋮ → Export to KML/KMZ → drop the file on this map; it imports with the geometry untouched (as do GPX and GeoJSON routes). Each route exports as its own TAK route package (b-m-r).

Layers are yours to define: click a name to rename, “+ Add layer” to add, ✕ to delete. Add points by coordinate (decimal, DMS or MGRS), “Pick on map”, or import CSV (name/lat/lon — or an mgrs column), GeoJSON, KML/KMZ or GPX dropped onto the map (KML/KMZ/GPX routes keep their source geometry exactly). Imports that carry points ask which layer to add them to — pick an existing layer or create a new one on the spot; a point in the wrong layer moves via the Layer dropdown in its popup, or select several and use “Move selected to layer…”. WhatsApp chat exports: export the chat from WhatsApp (with media if you want the photos) and drop the .zip straight on the map — shared pins and typed coordinates are both read, each point is named from the message next to it, sender and timestamp land in its notes, and photos sent with a pin are attached to that point, and a phone number quoted with a location goes into its notes. Pins shared as maps.app.goo.gl short links carry no coordinates at all — the scan counts them so you know what's missing; open those in a browser and paste the full URL. Coordinates buried in messages or documents: paste the text into Bulk paste (or drop a .docx / .pptx / .txt on the map) and every decimal, DMS and MGRS coordinate is found, named from the surrounding words, and offered as a tick-list. Icons use TAK / MIL-STD-2525 symbology plus your team's own ATAK iconset paths — set a whole layer's “Default icon”, click any marker to override it, or select points (checkbox, “in view”, or Shift-drag a box) and bulk-change icon / layer from the Selection box. Deleted something? Ctrl+Z. Click a marker → “Move (drag)” to reposition it, add Notes (→ TAK remarks) or attach photos/files — attachments travel inside the TAK package and open from the marker in ATAK. Routes: drag stops in “Edit stops”, Reverse, Re-snap, and ETAs at your planning speed. Every change flows into the exports and the autosave (very large attachments/imagery may exceed browser autosave — the .json save always keeps them). TAK packages import via ATAK/WinTAK (Import → Local, or drop into atak/tools/datapackage) — on first use, spot-check one point, route and area in your TAK build before pushing to the team, as shape handling varies slightly by version.

OPSEC: basemap tiles, “Snap to roads” (router.project-osrm.org) and the Google-Maps links are the only things that leave this device — work offline or untick them and everything stays in this file/browser. Tile requests go to the provider of the basemap you pick: OSM, Esri (Satellite / Sat hybrid), OpenTopoMap, Google (Google hyb) or Mapbox (Mapbox hyb — needs your own token, kept in this browser only). Note “Google hyb” uses the unofficial tile endpoint common in ATAK map-source files, not the paid Google API — it can break without notice and its use is a Google-ToS grey area; make it a team decision. Imagery age: on Satellite / Sat hybrid a small corner chip shows when the imagery at the centre of the view was captured (queries Esri's metadata service — needs internet), and “Imagery capture date” in Map & basemap gives full details for any clicked point. Google and Mapbox don't publish capture dates for their tiles. Terrain: “Hillshade relief” shades valleys and drainage over any basemap (Esri tiles); “Elevation profile” cross-sections two clicked points — and each route card's “Profile” button sections the whole route — with relief, climb and max slope from a 30 m elevation model (opentopodata.org, falling back to open-meteo.com; sampled coordinates go to that service). 30 m resolves valleys and large wadis, not narrow erosion gulleys — ground-truth those.
