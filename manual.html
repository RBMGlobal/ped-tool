PED Field Manual

PED is a single HTML file — and an Android app built from that same file — for working up an operational picture on a map and handing it to ATAK as a data package. Plot and edit in bulk here, where it is quick, then export once. Everything runs on the device you open it on.

—Quick start: a package into ATAK in five minutes

Sections 1–9 below follow the panels down the sidebar, in order. If you only ever do one thing with this tool, it is the sequence here.

  1. 1

    Open it

    Double-click PED_tool.html (any browser) or open the PED app. If you were working on something last time, a bar offers to Restore it — take it, or Start blank.

  2. 2

    Name a layer

    In Layers — key & filter, click the name Layer 1 and type what these points are — "Blocking positions", "Reported incidents". Set its Default icon so everything you add gets the right TAK symbol without touching each point.

  3. 3

    Get the locations in

    Three ways, all in Plot points: type a coordinate and press Add point; press Pick on map and click; or paste the messages you were sent into Bulk paste and press Scan for coordinates. Files — a WhatsApp export, CSV, KML, GPX, Word, PowerPoint — just get dropped onto the map. See section 5.

  4. 4

    Check each point

    Click a marker. Set its affiliation (hostile / friendly / …), its type, its Layer, and anything worth saying in Notes — notes become the marker's remarks in ATAK. Attach a photo if you have one.

  5. 5

    Export and import

    Export TAK — everything (one package) gives you a single .zip. In ATAK: Import Manager → Local SD and pick it (or drop the zip into atak/tools/datapackage first). In the Android app the export opens the share sheet — choose ATAK and it goes straight in.

Before you rely on it

On a new TAK build, export one point, one route and one area first and check they land the way you expect. Shape and icon handling varies a little between ATAK versions.

01Project — save & restore

Save (.json) writes everything — points, routes, areas, imagery overlays, attachments, custom icons, your planning speed — into one file. That file is the backup and the way you hand work to someone else. Load / import… opens it again, and is also the button for importing any other format.

Autosave is a safety net, not a backup

The tool saves to the browser's own storage as you work and offers it back next time you open the file. That storage belongs to that browser on that device — it does not travel with the HTML file, it is lost if the browser data is cleared, and very large attachments or imagery can exceed what it will hold. Save a .json at the end of anything you care about.

Why the same project file matters

Every item exports with an identifier built from the project it belongs to. Re-export from the same project and ATAK updates the markers you already sent. Start a fresh project and export the same points, and ATAK treats them as new ones — you get duplicates. So: one project file per operation, kept and reloaded.

Sentinel-2 — recent, dated imagery

The other imagery basemaps are the best available picture, which may be years old. Sentinel-2 is ESA's Copernicus constellation: a new pass over any point every 2–5 days, 10 m per pixel, every scene dated, free to use including commercially with attribution. PED shows the most recent pass in a window that is under a cloud limit, and the corner chip states which pass you are looking at and how cloudy it was — so "the track was open on 25 Aug" is a statement you can make from the map.

It works out of the box. A team instance ID ships in the tool (the “PED tool” configuration on the RBM Copernicus account, layer TRUE-COLOR-S2L2A — the atmospherically corrected L2A product). Tile use counts against that account's 30,000-tiles-a-month allowance; anyone with the file shares it, and it can be deleted and recreated in the dashboard at any time. To use your own instead: free account at dataspace.copernicus.eu → Configuration Utility → new configuration from the Simple WMS template → paste its Instance ID into the field under the basemap buttons. A typed ID is kept in that browser only and never written into a project file.

Set Up to (default today), the Window (default 20 days) and the Cloud limit (default 20%). The chip says which pass resulted; if it says no pass qualifies, widen the window or raise the cloud limit — in the wet season expect to trade cloud for recency.

Pushing Sentinel-2 into a TAK data package

Grab this view → TAK data package, under the Sentinel-2 settings, turns what is on screen into imagery the team carries: one press fetches the current view as a single picture at up to 10 m, drops it under Imagery — named by its pass date and cloud cover, e.g. S2 2026-08-29 (12% cloud), with the Copernicus attribution on the card — and exports it as a TAK data package. It imports into ATAK/WinTAK like every other package and shows under GRG/overlays.

  • Frame first. The grab is exactly the map view. Up to about 25 km across comes through at the full 10 m; wider grabs are automatically coarser and the card states the real m/px, so nobody mistakes a province grab for a detailed one.
  • Same pass as the screen. The grab uses the same date window and cloud limit as the live layer, so what lands in ATAK is what you were looking at.
  • It stays in the project. The grab is a normal imagery overlay afterwards — opacity slider, re-export as KMZ or in the all-imagery package, saved in the .json — so the picture the team acted on is on record with its date.
  • Size. A full-resolution grab is typically 1–3 MB in the package — fine over Starlink or a TAK server; think before queuing several on a thin phone link.

Flying a route on the M30T

DJI Pilot 2 on the RC Plus does not read TAK packages, GPX or plain KML — routes go in only as DJI's own wayline format. The M30T button on each route card exports exactly that: a KMZ carrying wpmz/template.kml and wpmz/waylines.wpml with the aircraft and payload set for the M30T. Copy it to the controller (USB or shared storage) and import via Flight Route → Import Route.

  • Stops become waypoints; the road geometry does not. An aircraft does not follow the road, so a snapped route's thousands of vertices are deliberately left out.
  • Defaults are safe, not decisions. 60 m above the launch point, 10 m/s, nose along the route, stop at each waypoint; on lost link the aircraft returns home, and it returns home at the end. Height, speed, camera actions and all of it are editable in Pilot 2 before flying — check every parameter there; the tool plans geometry, not the flight.
  • Heights are relative to the launch point, not to the ground under each waypoint. Rising ground along the route eats clearance — check the elevation Profile on the route card before flying a 60 m mission over a ridge.

Putting points on the M30T's map

Pilot 2 has no way to load a file of pins directly — its PinPoints are made on the controller, or synced down from DJI FlightHub 2, which is DJI's supported route for exactly this. DJI points (KML) in the Export section writes a points-only KML (your selection, or every point): each pin carries its ID and name, with the affiliation, DMS and notes in the description. Import it in FlightHub 2 → your project → Annotations → Import, and the pins appear on the map in Pilot 2 on every controller in the project. No routes or areas are included in this file, deliberately; the same file also opens in Google Earth.

Quota, zoom and licence

The account allows 30,000 tile requests a month. A screenful is roughly a dozen, so that is over two thousand views — ample for targeted looks, not for browsing a province. Tiles start at zoom 8: go to the place first on another basemap, then switch. Attribution (Contains modified Copernicus Sentinel data) is shown on the map and must stay on anything you publish from it. The widely used EOX "Sentinel-2 cloudless" mosaic is deliberately not offered: it is a static annual composite under a non-commercial licence.

Google hyb

This uses the unofficial tile endpoint that community ATAK map sources use — not the paid Google Maps API. It can stop working without notice and its use sits in a grey area of Google's terms. Treat switching it on as a team decision, not a default.

Imagery capture date

On Satellite and Sat hybrid, a small chip in the corner of the map shows when the imagery under the centre of your view was taken, and updates as you move. For a specific spot, press Imagery capture date and click it — you get the date, the resolution and the source. This needs internet, and only Esri publishes it; Google and Mapbox don't.

Terrain

Hillshade relief lays shaded relief over whichever basemap you are on, which makes valleys, wadis and drainage lines read at a glance. Elevation profile then takes two clicks and draws a cross-section between them with the drop, the relief and the steepest slope; each route card has a Profile button that does the same for the whole route.

Resolution

The elevation model is roughly 30 m. It resolves valleys and large wadis honestly. It will not show a narrow erosion gulley that could still stop a vehicle — ground-truth those.

Zoom to everything frames all your plotted work. Show data table swaps the map for a table of every point — the fastest way to check a batch you have just imported. Press it again for the map.

03Layers

Layers are yours to define — they are how you group the picture and how you export it in pieces. Click a layer's name to rename it. The tick box hides and shows it on the map. The count on the right is how many points it holds. ✕ deletes the layer and its points (Ctrl+Z brings them back). + Add layer makes another.

Default icon

Each layer has a Default icon — an affiliation, or a specific type such as Infantry or a coloured spot dot. Every point in the layer that you have not overridden individually follows it, so changing one dropdown re-symbolises the whole layer. Points you have set by hand keep what you gave them, and the tool tells you how many it left alone.

Moving points between layers

  • One point: open its popup and change the Layer dropdown. Pick ➕ New layer… to create one on the spot.
  • Several: select them, then use Move selected to layer… in Select & bulk edit — which also offers a new layer.
  • On import: anything you drop that contains points asks where to put them first. See section 5.

04Plotting points

In the Plot points box, choose the coordinate format (Decimal °, D° M′ S″ or MGRS), the layer, the affiliation and the type, then type the coordinate and press Add point. Or press Pick on map and click the position — Esc stops picking.

The marker popup

Click any marker. From top to bottom you get:

  • Its current type and layer, the coordinate in decimal, DMS and MGRS, and the exact CoT type it will export as.
  • Affiliation — seven buttons, click to change.
  • Type / role — unit types, sites, waypoint, or a coloured spot dot.
  • Layer — move it, including to a new layer.
  • Notes — free text; becomes the marker's remarks in ATAK.
  • Attachments — photos or files, which travel inside the data package and open from the marker in ATAK. Large images are downscaled automatically so packages stay transferable.
  • Move (drag) to reposition it, Delete to remove it, and the tick box to include it in a selected-points export.

Team iconset (ATAK)

If your ATAK devices already carry a custom iconset, copy an icon's path out of ATAK's Iconset Manager — it looks like 34ae1613-…/Ops/vcp.png — and add it under Team iconset (ATAK) with a name and a stand-in colour. It then appears in every type dropdown. Points using it export with that iconsetpath, so they render as your own symbol on the device; on this map they show as a coloured pin. Custom icons are saved with the project.

05Bringing coordinates in

Anything can be dropped straight onto the map, or opened with Load / import…. Anything containing points asks which layer first — an existing one, or a new layer named after the file. Where a file also holds routes or areas, you can skip its points and still take the rest.

CSV columns

Beyond position, the importer recognises name, id, layer, affiliation, role, notes and color (and common synonyms — callsign, group, remarks, lng, y/x). A layer column wins per row and creates layers as needed, so a spreadsheet can arrive pre-sorted.

Bulk paste — the everyday route

Paste anything into Bulk paste — WhatsApp messages, a sitrep, text out of Word or an email — and press Scan for coordinates. Every coordinate found comes back as a tick-list: names already filled in from the surrounding words, anything within ~15 m of an existing point flagged dup?. Untick the false hits, fix the names, choose the layer, and Add ticked points.

The marks do not have to be the proper ones. Seconds are read whether they are written as a double prime (″), a plain double quote ("), a curly quote, or — the common one, because it is the easy key on a phone — two apostrophes in a row (''). Degrees can be ° or º. Lat and lon can be separated by a comma, a semicolon, a pipe, a slash or nothing but a space, and the hemisphere letter can come before the numbers instead of after. What it will not accept is minutes or seconds of 60 or more, because those are not coordinates. A date-time group (“12 Sep 2026 1230”) is never read as a grid reference, even though it has the same shape as one.

The single-coordinate box reads what you typed, not what the dropdown says. Leave it on Decimal and paste DMS or an MGRS grid and it works out which it is. Two numbers with letters before or after them (S12.5 E7.6, 7.6E 12.5N) are read with the letters deciding which is which.

A number needs at least two decimal places to count, which is what stops dates, version numbers and phone numbers being read as positions. Where one message carries several locations, each one is named from the words next to it rather than from the whole sentence, so a report that runs "… X located around Dutsinma Road on Lat/Long …, and Y located around Kofar Fada Kuki on Lat/Long …" gives you two properly distinct points.

TAK data packages — the other direction

Drop a mission or data package (.zip) — or a bare .cot — onto the map and it is read back in: markers with their affiliation, role, colour, callsign and remarks; routes with their stops and the driven line between them; drawing shapes and range rings; and any photos or files attached to a marker. You are asked once which layer the markers should go to, the same as any other import.

This is what makes the tool work in both directions. If the plan has already been built in ATAK or WinTAK, you no longer rebuild it here to get it to a pilot — pull the package in, then send it straight back out as GPX, an Air Navigation CSV, or a WhatsApp message. It also means a package that came off someone else's tablet can be checked, corrected and pushed back out without ever leaving the map.

What survives the trip

A package exported from here and dropped straight back in returns the same picture: identical CoT types, the same colours (including spot-map dot colours, which travel in the marker's own colour field), your notes, and attachments back on the markers they belong to. The boilerplate the export appends to remarks — layer, name, grid, symbol label — is stripped back off on the way in, so a round trip does not accumulate it. Only what an operator actually typed comes back as notes.

Packages written before v1.14

From v1.14 a marker's remarks keep your note and the generated summary on separate lines, so reading a package back separates them exactly. Older packages ran the two together, and there is no certain way to tell where one ended — so an older package may come back with the layer name still attached to the note ("Manned 0600–1800 — Blocking positions"). Nothing is lost; tidy it in the popup if it bothers you. Re-export once and it is clean from then on.

What does not come across

Packages carry no layer structure, so everything lands in the one layer you pick — split it afterwards with Move selected to layer… if you want it separated. Imagery overlays inside a package are not read. Anything using a CoT type the tool does not model arrives as a plain point of the right affiliation rather than being dropped, and the toast tells you how many items it could not make sense of.

WhatsApp chat exports

In WhatsApp, open the chat → Export chat → With media if you want the photos. Drop the .zip straight onto the map. Out of it you get:

  • Shared pins as well as typed coordinates.
  • A name for each point, taken from the message beside the pin — or the sender and time if there is nothing to go on.
  • Notes carrying the sender and timestamp, the phone number quoted with that location, and the original message text — all of which end up in the ATAK remarks.
  • Photos sent with a pin, attached to that point and travelling inside the data package.

Short links carry nothing

A pin shared as a maps.app.goo.gl link contains no coordinates at all — not in the export, not anywhere offline. The scan counts them and tells you how many it found so nothing goes unnoticed; open those links in a browser and paste the full URL from the address bar. Photos sent normally have their location data stripped by WhatsApp, so a photo without a pin beside it gives no position either.

06Routes

Paste a Google Maps directions link — a full .../maps/dir/… URL that contains coordinates — name it, and press Add route. Stops are read in order and each leg is snapped along roads at full resolution, around 5 m fidelity. Set Planning speed and every route card shows distance and an ETA.

Each route card carries Edit stops (drag the stops, the route re-snaps), Reverse, Profile for a terrain cross-section of the whole route, and its own TAK export.

Road choice, not road accuracy

Snapping follows OpenStreetMap routing. The line sits on the road accurately, but at some junctions OSM will choose a different road than Google would. Eyeball the route before anyone drives it. For Google's exact line, build the route in Google My Maps, export it to KML/KMZ, and drop that on the map — imported geometry is kept untouched, and the route list labels it as imported.

A shared maps.app.goo.gl short link carries no coordinates; the tool opens it for you so you can copy the full URL out of the address bar.

07Threat areas

Draw area — click each corner, then double-click or press Enter to close it. Draw circle — click the centre, then click the edge to set the radius. Esc cancels either.

Each shape can be renamed, recoloured and given notes, and exports as a TAK drawing — polygons as u-d-f, circles as u-d-c-c with a true radius, so they arrive as editable shapes rather than pictures.

08Imagery overlays

Add imagery (GeoTIFF / image)… — or drop the file on the map. A georeferenced .tif places itself. A plain PNG or JPG (a screenshot, an air photo, a scanned annex) is placed with three corner handles you drag until it sits right.

Each overlay gets its own transparency slider and saves with the project. Export TAK package — all imagery sends them to ATAK as KMZ ground overlays (GRGs), and they are included when you export everything in one package.

Package size

Imagery is by far the biggest thing you can put in a package. Large overlays make files that are slow to move onto a device and can push the browser autosave past its limit — the .json save always keeps them.

09Select & bulk edit

This is what makes the tool worth using over editing in ATAK. Select points by:

  • the tick box in a marker's popup,
  • Box select — drag a rectangle, or just Shift+drag on the map,
  • Select points in view — everything currently on screen.

Then, on the whole selection at once:

  • change the icon — any affiliation, type or spot-dot colour,
  • Move selected to layer…, existing or new,
  • Delete selected points, undone with Ctrl+Z,
  • export just the selection as a package, KML or CSV.

Naming the file

Every export stops and asks for a file name first, with the generated one filled in and the name part already selected — so Enter accepts it unchanged, or you type straight over it. The extension is put back if you leave it off, and Esc or Cancel abandons the export without saving anything.

Give a package the operation's name and it arrives on someone's device saying what it is, rather than PED-ALL-20260830_1040.zip. If you would rather not be asked, untick Ask me for a file name before saving under the export buttons — the tool remembers that choice.

One name for a batch

Export TAK — one package per layer asks once, not once per file. Type Op Kaduna and you get Op Kaduna - Blocking positions.zip, Op Kaduna - Reported incidents.zip and so on — the layer name is appended so the packages stay apart.

Names get simplified, and that is deliberate

Browsers quietly refuse a download name they do not like and save it as download instead — Chrome rejects the whole name over a single accent or an em dash. So names are folded to plain characters on the way out: Café — Zaria recce saves as Cafe - Zaria recce.gpx. Slashes, colons and the other characters a file system will not take are dropped for the same reason.

Getting a package into ATAK

  • Android app: the export opens the share sheet — choose ATAK.
  • ATAK, file already on the device: Import Manager → Local SD → pick the .zip.
  • ATAK, moving it across: copy the zip into atak/tools/datapackage, then Import Manager.
  • WinTAK: File → Import.

Getting points into Air Navigation Pro

Two ways, depending on whether you are on the tablet or at a computer.

  • On the device — Export GPX (.gpx). Put the file on the phone or tablet (email it, drop it in cloud storage, whatever you already do), open it, and choose Share or Open with → Air Navigation Pro. Your points arrive as user waypoints. Each route arrives twice over: as a route of its stops, which is what you navigate, and as a track of the full driven line, which is what you look at. GPX is a standard format, so the same file works in most other GPS apps.
  • At a computer — Export Air Navigation CSV. Import it in Air Navigation Manager. This one carries more: each point's layer becomes its tag, so your layers survive as groups you can filter, and every icon and colour is translated to the nearest one Air Navigation offers.

Two things the translation changes

Air Navigation's palette has no red, so hostile and suspect points come across as Pink — still the most alerting colour available, but check it reads the way you expect before briefing from it. And its waypoint names accept a narrower set of characters than the tool does, so brackets, dashes and accents are stripped out: "BP 3 (Dutsinma Rd)" becomes "BP 3 Dutsinma Rd".

Choosing which locations go

Open a point and you will find two tick boxes at the bottom of its popup: Select for TAK / KML export, which you already know, and Send to Air Navigation Pro. They are separate lists on purpose — the set of grids a pilot needs is rarely the same as the set going into a data package, and building one should not disturb the other. Marked points carry a dashed blue ring on the map so you can see the pilot's list at a glance, and the count sits above the three export buttons.

Mark selected turns whatever you currently have selected into marks in one go — handy after a box-drag or Select points in view. Clear marks empties the list.

What each export sends

All three Air Navigation exports use the marked points. Mark nothing and they fall back to what they did before: your TAK selection if you have one, otherwise every point on the map. Whichever of the two is doing the work, they carry only those points, with no routes attached.

The GPX brings your routes along only when nothing is marked and nothing is selected. That is the one case to watch — with both counters at 0, "export everything" is taken literally. If you want every point but no routes, press Select points in view with the whole AO in frame, or Mark selected after it.

To send one layer and nothing else — just the reported incidents, say — untick every other layer in Layers — key & filter, press Select points in view (it skips hidden layers entirely), then Mark selected if you want that list to stick around.

Waypoint elevations are exported as 0 unless you tick Look up ground elevations, which fetches them from the same terrain service the elevation profile uses — so it needs internet, and the coordinates go to that service. All three of these use your current selection if you have one, and every point if you don't.

Sending an updated set — and why you get duplicates

Move a point, export again, open the new file on the iPad, and Air Navigation Pro adds a second waypoint and keeps the old one. That is the app's behaviour on the device, not something the file can change: a GPX carries no field that says "this is the same waypoint you already have", and Air Navigation's own manual documents no merge or replace option for an on-device import. Nothing PED can put in the file will make it update in place.

The route that does update: Air Navigation Manager

Export Air Navigation CSV, then import it in Air Navigation Manager on a computer with the Overwrite box ticked. Their documentation is explicit about it: "By default, existing waypoints will not be replaced. Click on the Overwrite checkbox to ensure the items are updated." The corrected waypoints then sync down to the iPad instead of piling up beside the old ones.

Every point now carries a permanent waypoint identifier — worked out the first time you export it and saved with the project — so an updated export points at the waypoint Air Navigation already holds. Moving a point keeps its identifier, and so does renaming it, which is what makes an Overwrite import correct the existing waypoint rather than add a twin.

Test it on two waypoints before you trust it with fifty

Air Navigation's documentation says Overwrite updates existing items but does not say which field it matches on. The identifier is the only sensible candidate and it is a mandatory column in their format, but that is our inference and not something they state. Send two waypoints, move one, re-import with Overwrite, and check you end up with two rather than three before you rely on it operationally.

If you are working iPad-only and the duplicates are piling up, the blunt instrument is Air Navigation's own Restore waypoints → Confirm replacement, which swaps the whole user-waypoint set for a backup rather than merging into it.

Sending locations over WhatsApp

Copy for WhatsApp is for the case where there is no time to move a file about: you need a pilot to have three grids on his iPad in the next two minutes. Select the points, press the button, and the message is on your clipboard — paste it into the chat and send.

What the pilot receives is in two halves, and either one on its own is enough:

  • The locations written out — numbered, named, with decimal latitude and longitude to five places. Readable on any phone, forwardable to anyone, and still useful if the person has no Air Navigation Pro at all.
  • A link that loads them into the app — an airnavpro://add-waypoints link carrying every location, its elevation, a short identifier and its name. Opening it on a device with Air Navigation Pro installed adds them all as user waypoints in one go, with nothing to download and no internet needed at the far end.

The link may not be tappable — say so when you send it

WhatsApp only turns ordinary web addresses into tappable links reliably. This one is an app link, so in many chats it will arrive as plain text. That is why the message itself says "tap the link, or paste it into Safari": the pilot presses and holds the link, copies it, pastes it into the Safari address bar and presses go — Air Navigation Pro opens with the waypoints in it. Worth telling him once, the first time, so he is not left poking at text that will not respond.

What gets trimmed, and why

Names in the link are cut to the characters Air Navigation accepts and their spaces are encoded, because a space would end the link where WhatsApp stops reading it — so "FOB — main gate" travels as FOB%20main%20gate and arrives as "FOB main gate". Identifiers are shortened to about ten characters and made unique. The written-out list above it keeps the real names untouched, so nothing is actually lost. Routes are never included: this is for sending positions, not a plan.

If the clipboard is blocked — some browsers refuse it unless the page has focus — the message appears in a box under the button instead. Select it and copy it by hand; nothing is lost.

What arrives

Points come in as markers of the right affiliation and type, carrying your notes as remarks, your attachments as files that open from the marker, and — for spot dots and team icons — the right colour and iconset path. Routes arrive as TAK routes with their full geometry, areas as editable shapes. Everything is marked to persist rather than expire.

Re-exporting

Export the same project twice and ATAK updates the items rather than duplicating them — which is why the project .json is worth keeping. Change something here, export again, and the picture on the device corrects itself.

11The web link & the Android app

Opening it from a web link

Where it lives

rbmglobal.co.uk/ped-tool/ — the tool, always the current version.
rbmglobal.co.uk/ped-tool/manual.html — this manual.

There is a Manual link in the top-right corner of the tool itself, and another at the top of its Help & OPSEC section, so nobody has to go looking for this page. Nobody has to be sent a file either — open the link and the tool is there, always the current version. On a phone or tablet, open it once and use Add to Home Screen (Chrome: menu → Add to Home screen; Safari: the share button). It installs under its own icon — the orange diamond marked PED — so it is easy to find among the other apps. From then on it launches like an app and keeps working with no signal: the tool, your saved work and every function are held on the device.

Offline means the tool, not the map

Basemap tiles come from the provider each time, so out of signal you get a blank map background with all your points, routes and areas on it — exactly how the local HTML file behaves today. Imagery you need in the field should be brought in as a GeoTIFF overlay, which is stored with the project.

From a browser, exports download to the device's Downloads folder — open ATAK's Import Manager → Local SD and pick the file from there.

The Android app

The app is the same tool wrapped for Android, so anything in this manual applies to both. The one difference is exports: instead of downloading, they open the system share sheet, so you can hand a package to ATAK on the same device without touching a cable.

  • Installing: copy PED_v1.7_debug.apk to the device, open it from the Files app, allow installing unknown apps when asked.
  • Updating: install the new APK over the old one. Your autosaved work survives.
  • Permissions: internet only, for basemap tiles and road snapping. It is fully usable offline.
  • Requirements: Android 7 or later.

Before switching build machines

Updates only install over the top while every APK is signed with the same key. An APK built somewhere else has to be uninstalled first, which wipes the autosave. Save your project to .json before any update you are unsure about.

CThings that catch people out

  • Short links are empty. maps.app.goo.gl pins carry no coordinates. Open them and copy the full URL.
  • Autosave is not a backup. It lives in one browser on one device. Save the .json.
  • Start from the same project file each time, or re-exports arrive in ATAK as duplicates instead of updates.
  • Snapped routes follow OSM's road choice, which is occasionally not Google's. Look at the line before it is driven.
  • 30 m elevation misses narrow gulleys. It is honest about valleys, not about erosion channels.
  • WhatsApp strips photo location data. A photo alone is not a position.
  • Imagery dates only exist on the Esri basemaps. Google and Mapbox don't publish theirs.
  • Big imagery makes big packages — check the file size before trying to move one onto a device in the field.
  • Spot-check a new TAK build with one point, one route and one area before pushing to the team.
